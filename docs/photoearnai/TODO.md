# PhotoEarnAI outcomes

## PhotoEarnAI identity and clean-room boundary

- [x] The browser product is named **PhotoEarnAI** in the document title, visible wordmark, menus, dialogs, status copy, and server banner.
- [x] The implementation is based on the supplied open-source clean-room prototype and PhotoCraft architectural reference.
- [x] Photopea is used only as a public behavior/layout reference; no proprietary Photopea source, bundles, fonts, logos, or assets are copied.
- [x] The project documents the current implementation boundary and future format milestones instead of claiming unsupported parity.

## Bilingual Thai and English interface

- [x] The UI supports Thai and English as selectable languages.
- [x] Switching language updates visible menus, tool labels, panel headings, buttons, dialogs, extension labels, and status copy without reloading the page.
- [x] The selected language is persisted locally and the interface includes an accessible language control.

## Core editor workflow

- [x] The app opens with a sample layered document and supports local new-document, image import/drop, layer creation, duplication, ordering, visibility, opacity, blend mode, merge, deletion, undo, redo, zoom, pan, brush, eraser, bucket, shape, text, eyedropper, and export workflows from the supplied prototype.
- [x] Text layers can be selected, edited, resized, recolored, and assigned a font through the Text editor flow.
- [x] Project JSON saves document metadata and layer pixels, and can be loaded back in the same browser.

## User-owned extensibility

- [x] Users can add custom tools through the Studio panel; a registered custom tool appears in the tools palette and can run its declared action.
- [x] Users can add presets with a name, category, and JSON settings; presets can be applied to the active layer.
- [x] Users can add filters with a name and pixel callback definition; filters are available through the Studio panel and execute against the active layer.
- [x] Users can add plug-ins as local JavaScript modules through a file picker; the app records the plug-in manifest, capability, and local-only status.
- [x] Users can add fonts with the browser FontFace API, choose the active document font, and keep the font in the current browser session.
- [x] Users can place a custom watermark or logo as a named layer with opacity, scale, position, and tiled settings.
- [x] Custom extension metadata is persisted in localStorage and is represented in project JSON.

## Run and delivery

- [x] The app serves on the managed WebDev runtime port and exposes `GET /manus-routes.json` with the root route.
- [x] JavaScript, HTML, CSS, and JSON diagnostics are registered for the project.
- [x] A deterministic smoke check validates extension registry persistence/normalization and route manifest validity.
- [ ] Full browser interaction coverage for every tool and every file format remains open for a future milestone.

## PSD and video processing integrations

- [x] File → Open PSD loads the lazy ag-psd 25 browser adapter, shows `Parsing PSD via ag-psd WASM...`, imports raster layers/groups, maps common blend modes, retains text/mask/effect metadata, and reports the parsed layer count with a parse→write→parse roundtrip count.
- [x] File → Export PSD (ag-psd WASM) downloads a real `.psd` generated by `writePsd`; the integration is isolated in `js/core/psdWasm.js`.
- [x] Video UI accepts MP4/WebM/MKV/MOV through file picker or canvas drop, samples at `fps=2`, creates one layer per frame, and shows progress through `#ffmpeg-progress`.
- [x] Video UI exposes Export MP4 (`libx264`) and Export GIF (palette/lanczos-style paletteuse pipeline) through `js/core/ffmpegWasm.js`, with a native HTMLVideoElement fallback when optional ffmpeg.wasm cannot load.
- [ ] Full PhotoCraft PSD roundtrip fixture parity of 307/309 and complete Photoshop coverage for all 27 blend modes, masks, text, and effects requires the upstream fixture corpus and remains open.

## Advanced non-destructive editing

- [x] Brush Engine exposes size/opacity/hardness plus Shape Dynamics, Scattering, Texture, and spacing controls through `brushEngine.js`, `brushToolAdvanced.js`, and `brushPanel.js`.
- [x] Smart Objects store source identity, lossless transform metadata, and smart-filter records without baking the source pixels.
- [x] Adjustment Layers provide Curves, Levels, and HSL metadata and apply non-destructive processing during compositing.
- [x] Layer Styles provide non-destructive Drop Shadow and Bevel metadata and render them at composition time.
- [ ] Pixel-perfect parity with all 67 PhotoCraft brush concepts and the complete Rust/WASM smart-object/adjustment/style implementation remains open.

## Photopea-style default layout and tool rail

- [x] Opening PhotoEarnAI defaults to Move Tool (V), keeps the canvas unobstructed, places the full tool rail on the left, and keeps Advanced Brush controls hidden until Advanced Brush is selected.
- [x] The left rail includes Move (V), Rectangular Marquee (M), Lasso (L), Crop (C), Eyedropper (I), Brush (B), Advanced Brush Engine (Shift+B), Clone Stamp (S), Eraser (E), Gradient (G), Paint Bucket (K), Blur, Text (T), Pen (P), Shape (U), Hand (H), and Zoom (Z).
- [x] Foreground defaults to `#0e8aef`, Background defaults to white, the swap control remains available, and Virtual Keys opens a Ctrl/Alt/Shift + No Touch popover near the bottom of the left rail.
- [x] Lasso and rectangular marquee show selection feedback; Crop applies a bounded document crop; Gradient, Blur, Clone Stamp, Pen, and Advanced Brush have working pointer paths rather than placeholder buttons.

## Video import recovery

- [x] Video import no longer waits for `loadedmetadata` after the event has already fired; metadata and seek listeners are registered before loading, with decode errors and a 15-second timeout.
- [x] FFmpeg loading uses only the published `coreURL` and `wasmURL` files; the nonexistent worker URL was removed so the ffmpeg.wasm path can initialize before falling back to HTML video decoding.

## Interactive tool fixes

- [x] Clone Stamp now captures an immutable source canvas on Alt-click, supports a Virtual Keys Alt modifier, auto-seeds a source on first paint, and stamps the captured pixels instead of drawing onto the same canvas as its source.
- [x] Blur now copies the active layer, clips the operation to the brush-radius circle, and applies blur only where the pointer is painted rather than blurring or missing arbitrary full-layer regions.
- [x] Pen Tool opens the text-entry flow and writes the entered text at the clicked document coordinate, matching the requested pen-for-text workflow.
- [x] Virtual Keys contains clickable Ctrl, Alt, and Shift buttons with active state; Alt affects Clone Stamp source selection and the controls are no longer display-only.
- [x] Pen now remains in drawing mode for the full pointer stroke and renders a thin freehand signature; it no longer opens a text prompt or draws an unwanted straight line on pointer-up.
- [x] Video export sorts animation frames in ascending order, validates that frames exist, downloads the FFmpeg output with a real filename, and falls back to MediaRecorder for MP4/WebM when FFmpeg initialization or encoding fails.
- [ ] GIF export still requires ffmpeg.wasm because browser MediaRecorder does not provide a GIF encoder.
- [x] GIF export initializes FFmpeg with the explicit jsDelivr `@ffmpeg/ffmpeg@0.12.10/dist/esm/worker.js` worker instead of the esm.sh default worker, preventing the embedded Preview cross-origin Worker construction error.
- [x] FFmpeg runtime imports, worker, core, and WASM now use jsDelivr URLs; the runtime no longer imports the esm.sh package entrypoint that produced the reported Worker error.
- [x] Virtual Keys are latched toggles with a NoTouch reset button and synchronize physical Ctrl/Alt/Shift keydown and keyup events.
- [x] Clone Stamp shows its usage in the status bar, stores a source snapshot, and applies the source-to-destination offset while stamping.
